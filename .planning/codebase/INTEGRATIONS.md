# External Integrations

**Analysis Date:** 2026-02-10

## APIs & External Services

**Volkswagen Connect API:**
- Service: VW-Group vehicle data platform (WeConnect)
- What it's used for: Retrieve vehicle status, control features (charging, climatisation, locking, honk & flash)
- SDK/Client: aiohttp (native HTTPS requests)
- Auth: OAuth2 (Authorization Code Flow with JWT tokens)
- Implementation: `volkswagen/vw_connection.py`, `volkswagen/vw_vehicle.py`

**Volkswagen Identity Provider (Region-specific):**
- **EMEA (Europe):** OAuth endpoint at base API
  - Config endpoint: `https://emea.bff.cariad.digital/login/v1/idk/openid-configuration`
  - Auth: Standard OAuth2 authorization code flow

- **North America (US/CA):** Separate identity provider (2026)
  - Identity endpoint: `https://identity.na.vwgroup.io`
  - Config endpoint: `https://identity.na.vwgroup.io/.well-known/openid-configuration`
  - Client ID: `b680e751-7e1f-4008-8ec1-3a528183d215@apps_vw-dilab_com`
  - Redirect URI: HTTPS callback to base API (`https://b-h-s.spr.us00.p.con-veh.net/oidc/v1/oauth/callback`)
  - Scope: `openid email` (minimal, app does not use PKCE despite server support)
  - Auth: Standard OAuth2 authorization code flow

**Configuration:**
- Auto-detection from `country` parameter in `Connection` class
- `COUNTRY_TO_REGION` mapping: US/CA → NA, DE/FR/UK/etc → EMEA (see `vw_const.py` lines 68-93)
- NA region supports endpoint discovery from 6 candidates (lines 52-59 in `vw_const.py`)

## Data Storage

**Databases:**
- None - This is a client library, not a backend service
- Vehicle state stored in-memory in `Vehicle` class (`_states` dict in `vw_vehicle.py`)

**File Storage:**
- None - Library does not write files
- Generated: `volkswagencarnet/version.py` (auto-generated by setuptools_scm from git tags)

**Caching:**

- Request tracking: `Vehicle._requests` tracks in-progress operations to prevent concurrent requests
- Service discovery: `Vehicle._services` cached per vehicle after first discovery call

## Authentication & Identity

**Auth Provider:**
- Volkswagen OAuth2 (Identity service)
- Separate endpoints for EMEA and North America regions

**Implementation:**
- OAuth2 Authorization Code Flow (RFC 6749)
- Entry point: `Connection.doLogin()` in `vw_connection.py` (line 166)
- Token types: JWT (ID token + Access token)
- Token validation: Uses PyJWT to verify tokens before use
- Region-specific credentials:
  - EMEA Client ID: `a24fba63-34b3-4d43-b181-942111e6bda8@apps_vw-dilab_com`
  - NA Client ID: `b680e751-7e1f-4008-8ec1-3a528183d215@apps_vw-dilab_com` (confirmed 2026)
- Automatic token refresh before expiry (checked in `validate_tokens()` method)
- Login flow steps (lines 210-350 in `vw_connection.py`):
  1. Fetch OpenID configuration
  2. Request authorization page (login form)
  3. Extract state token via BeautifulSoup HTML parsing
  4. POST username/password credentials
  5. Extract authorization code from redirects
  6. Exchange code for tokens
  7. Validate and store tokens

## API Endpoints

**EMEA Region:**
- Base API: `https://emea.bff.cariad.digital`
- Home region: `https://msg.volkswagen.de`
- OpenID config: `{base_api}/login/v1/idk/openid-configuration`
- Vehicle list: `{base_api}/vehicle/v2/vehicles`
- Capabilities discovery: `{base_api}/vehicle/v1/vehicles/{vin}/capabilities`
- Service status: `{base_api}/vehicle/v1/vehicles/{vin}/selectivestatus`

**North America Region:**
- Base API: `https://b-h-s.spr.us00.p.con-veh.net` (confirmed 2026)

- Fallback candidates for base API (if primary not working, lines 52-59 in `vw_const.py`):

## Vehicle API Services

Services available via capabilities discovery (defined in `vw_const.py` lines 207-237):
- **access** - Door locks, windows, overall status
- **charging** - Battery status, charging state, plug status, charge settings
- **climatisation** - Climate control, settings, timers
- **measurements** - Odometer, ranges, fuel level, battery temperature
- **vehicleHealth** - Maintenance status, inspection due
- **fuelStatus** - Fuel levels and range per engine type
- **departure** - Departure timers and profiles
- **parkingPosition** - GPS coordinates
- **tripStatistics** - Trip history and statistics
- **readiness** - Vehicle connection state and battery power
- **honkAndFlash** - Horn and light control
- **vehicleLights** - Light status
- **userCapabilities** - User feature access
- **batteryChargingCare** - Legacy battery care settings
- **batterySupport** - Legacy battery support

## Rate Limiting

**Behavior:**
- VW API implements HTTP 429 throttling
- Library retries up to 3 times with exponential backoff (defined in `vw_connection.py` line 49: `MAX_RETRIES_ON_RATE_LIMIT = 3`)
- Returns `{"state": "Throttled"}` when rate limited
- Logs warnings about throttling

## Security Features

**Security PIN (SPIN):**
- Required for: Lock/unlock, honk & flash operations
- Implementation: SHA-512 hash with challenge (in `vw_connection.py`)
- Enforcement: Minimum 3 remaining attempts required to prevent lockout
- Custom exception: `SPINError` (in `vw_exceptions.py`)

**HTTPS:**
- All API communication over HTTPS
- Certificate validation (aiohttp default)

**User-Agent Spoofing:**
- Masquerades as Android Volkswagen app: `Volkswagen/3.51.1-android/14` (line 13 in `vw_const.py`)
- Required to match official app for API acceptance

## Terms & Conditions

**Handling:**
- Custom exception: `TermsAndConditionsError` (in `vw_exceptions.py`)
- When raised: User must accept terms on VW portal before API access is granted
- Not automatically handled by library
